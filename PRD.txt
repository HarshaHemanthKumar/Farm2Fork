SECTION 0: PROJECT SUMMARY
================================================================================

NAME          : Farm2Fork
TYPE          : Two-sided marketplace (Farmer ↔ Consumer) + micro-logistics layer
REGION        : India (INR currency, Indian phone numbers, WhatsApp-style UX)
LANGUAGES     : English + Hindi (i18n ready, launch in English first)

CORE ACTORS:
  1. FARMER       — lists produce, receives orders, gets paid
  2. CONSUMER     — browses, orders, pays, tracks delivery
  3. DELIVERY     — auto driver or bike courier, picks up from farm, drops to consumer
  4. ADMIN        — platform operator, manages disputes, payouts, onboarding

CORE FLOWS:
  A. Farmer lists produce → Consumer orders → Delivery picks up → Consumer receives
  B. Community Basket: 10 families pool orders → single pickup → split delivery
  C. Farmer gets paid via Stripe (INR) after delivery confirmation

SECTION 2: DATABASE SCHEMA (PostgreSQL — Sequelize Models)
================================================================================

All tables use UUID primary keys (uuid_generate_v4()).
Enable extension first: CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
All timestamps: createdAt, updatedAt (Sequelize auto-manages).
Soft deletes: deletedAt (use paranoid: true in Sequelize).

--- TABLE: users ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
phone           VARCHAR(15) UNIQUE NOT NULL          -- E.164 format: +919876543210
name            VARCHAR(100) NOT NULL
role            ENUM('farmer','consumer','delivery','admin') NOT NULL
profile_photo   TEXT                                 -- S3 URL
language        VARCHAR(5) DEFAULT 'en'              -- 'en' or 'hi'
is_active       BOOLEAN DEFAULT true
stripe_customer_id  VARCHAR(100)                     -- for consumers
stripe_account_id   VARCHAR(100)                     -- for farmers (Express account)
stripe_onboarding_complete BOOLEAN DEFAULT false
fcm_token       TEXT                                 -- Firebase push token
created_at      TIMESTAMPTZ DEFAULT NOW()
updated_at      TIMESTAMPTZ DEFAULT NOW()
deleted_at      TIMESTAMPTZ                          -- soft delete

--- TABLE: farmer_profiles ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
user_id         UUID NOT NULL REFERENCES users(id)
farm_name       VARCHAR(150) NOT NULL
farm_address    TEXT NOT NULL
farm_lat        DECIMAL(10,8) NOT NULL
farm_lng        DECIMAL(11,8) NOT NULL
farm_size_acres DECIMAL(6,2)
description     TEXT
is_verified     BOOLEAN DEFAULT false
bank_account_last4 VARCHAR(4)                        -- display only

--- TABLE: delivery_profiles ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
user_id         UUID NOT NULL REFERENCES users(id)
vehicle_type    ENUM('bike','auto','van') NOT NULL
vehicle_number  VARCHAR(20) NOT NULL
license_number  VARCHAR(30) NOT NULL
service_radius_km INTEGER DEFAULT 10
is_available    BOOLEAN DEFAULT false
current_lat     DECIMAL(10,8)
current_lng     DECIMAL(11,8)
rating          DECIMAL(3,2) DEFAULT 5.00

--- TABLE: produce_categories ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
name_en         VARCHAR(100) NOT NULL
name_hi         VARCHAR(100) NOT NULL
icon_url        TEXT
display_order   INTEGER DEFAULT 0

--- TABLE: listings ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
farmer_id       UUID NOT NULL REFERENCES users(id)
category_id     UUID NOT NULL REFERENCES produce_categories(id)
title           VARCHAR(200) NOT NULL
description     TEXT
price_per_kg    DECIMAL(8,2) NOT NULL                -- in INR paise stored as decimal
unit            ENUM('kg','dozen','piece','bunch') DEFAULT 'kg'
available_qty   DECIMAL(8,2) NOT NULL
min_order_qty   DECIMAL(8,2) DEFAULT 0.5
harvest_date    DATE NOT NULL
expiry_date     DATE NOT NULL
images          TEXT[]                               -- array of S3 URLs
is_active       BOOLEAN DEFAULT true
is_organic      BOOLEAN DEFAULT false
status          ENUM('draft','active','sold_out','expired') DEFAULT 'draft'
pincode         VARCHAR(6) NOT NULL                  -- for geo filtering
lat             DECIMAL(10,8)                        -- farm lat (denormalized for speed)
lng             DECIMAL(11,8)
total_sold_kg   DECIMAL(8,2) DEFAULT 0
view_count      INTEGER DEFAULT 0

--- TABLE: orders ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
consumer_id     UUID NOT NULL REFERENCES users(id)
listing_id      UUID NOT NULL REFERENCES listings(id)
farmer_id       UUID NOT NULL REFERENCES users(id)
delivery_id     UUID REFERENCES users(id)            -- assigned delivery partner
basket_id       UUID REFERENCES community_baskets(id) -- null if individual order
quantity        DECIMAL(8,2) NOT NULL
unit_price      DECIMAL(8,2) NOT NULL                -- snapshot at time of order
subtotal        DECIMAL(10,2) NOT NULL               -- quantity * unit_price
delivery_fee    DECIMAL(8,2) NOT NULL DEFAULT 0
platform_fee    DECIMAL(8,2) NOT NULL DEFAULT 0      -- 5% of subtotal
total_amount    DECIMAL(10,2) NOT NULL
status          ENUM('pending_payment','payment_failed','confirmed','farmer_accepted',
                     'ready_for_pickup','picked_up','delivered','cancelled','refunded')
                DEFAULT 'pending_payment'
delivery_address TEXT NOT NULL
delivery_lat    DECIMAL(10,8) NOT NULL
delivery_lng    DECIMAL(11,8) NOT NULL
stripe_payment_intent_id VARCHAR(100)
stripe_transfer_id VARCHAR(100)
farmer_payout_amount DECIMAL(10,2)                   -- total - platform_fee - delivery_fee
delivery_instructions TEXT
otp_for_delivery VARCHAR(6)                          -- consumer shows this to delivery partner
delivered_at    TIMESTAMPTZ
cancelled_at    TIMESTAMPTZ
cancellation_reason TEXT

--- TABLE: community_baskets ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
listing_id      UUID NOT NULL REFERENCES listings(id)
name            VARCHAR(150) NOT NULL                -- e.g. "Koramangala Tomato Group"
created_by      UUID NOT NULL REFERENCES users(id)
target_families INTEGER DEFAULT 10
current_families INTEGER DEFAULT 0
min_total_kg    DECIMAL(8,2) NOT NULL                -- minimum order to qualify
current_total_kg DECIMAL(8,2) DEFAULT 0
status          ENUM('open','locked','confirmed','fulfilled','expired') DEFAULT 'open'
expires_at      TIMESTAMPTZ NOT NULL                 -- 48 hours from creation typically
pincode         VARCHAR(6) NOT NULL
delivery_lat    DECIMAL(10,8)                        -- single delivery point
delivery_lng    DECIMAL(11,8)
delivery_address TEXT
notes           TEXT

--- TABLE: basket_members ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
basket_id       UUID NOT NULL REFERENCES community_baskets(id)
consumer_id     UUID NOT NULL REFERENCES users(id)
order_id        UUID REFERENCES orders(id)
quantity_kg     DECIMAL(8,2) NOT NULL
joined_at       TIMESTAMPTZ DEFAULT NOW()
UNIQUE(basket_id, consumer_id)

--- TABLE: reviews ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
order_id        UUID NOT NULL REFERENCES orders(id) UNIQUE
reviewer_id     UUID NOT NULL REFERENCES users(id)
reviewee_id     UUID NOT NULL REFERENCES users(id)
rating          INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5)
comment         TEXT
type            ENUM('consumer_to_farmer','consumer_to_delivery','farmer_to_consumer')

--- TABLE: notifications ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
user_id         UUID NOT NULL REFERENCES users(id)
title           VARCHAR(200) NOT NULL
body            TEXT NOT NULL
type            VARCHAR(50) NOT NULL                 -- 'order_update','basket_update', etc.
data            JSONB                                -- extra payload
is_read         BOOLEAN DEFAULT false
sent_at         TIMESTAMPTZ DEFAULT NOW()

--- TABLE: delivery_assignments ---
id              UUID PRIMARY KEY DEFAULT uuid_generate_v4()
order_id        UUID NOT NULL REFERENCES orders(id)
delivery_id     UUID NOT NULL REFERENCES users(id)

SECTION 3: BACKEND API — ALL ENDPOINTS
================================================================================

BASE URL (local dev): http://localhost:3000/api/v1
BASE URL (prod)      : https://api.kisanconnect.in/api/v1

AUTH MIDDLEWARE: All protected routes require header:
  Authorization: Bearer <jwt_token>

JWT PAYLOAD: { userId, role, phone, iat, exp }
JWT EXPIRY: 7 days
REFRESH: Re-issue on each login (no refresh token at MVP)

--- AUTH ROUTES (/auth) ---

POST /auth/otp/send
  Body: { phone: "+919876543210" }
  Action: Generate 6-digit OTP → hash with bcrypt → store in otp_sessions
          → call MSG91 API to send SMS
  Response: { success: true, message: "OTP sent" }

POST /auth/otp/verify
  Body: { phone: "+919876543210", otp: "123456" }
  Action: Validate OTP → if user exists return token → if not, return needsRegistration
  Response: { token, user } OR { needsRegistration: true, phone }

POST /auth/register
  Body: { phone, name, role, fcm_token }
  Action: Create user → if role=farmer create farmer_profile shell
          → if role=delivery create delivery_profile shell
          → create Stripe customer if role=consumer
          → return JWT
  Response: { token, user }

POST /auth/logout
  Protected. Body: {}
  Action: Invalidate FCM token (set to null)

--- LISTING ROUTES (/listings) ---

GET /listings
  Query params: pincode, lat, lng, radius_km(default 20), category_id,
                min_price, max_price, is_organic, sort(price_asc|price_desc|newest)
                page(default 1), limit(default 20)
  Auth: Optional
  Action: Fetch active listings within radius using Haversine formula in SQL:
    WHERE (6371 * acos(cos(radians(:lat)) * cos(radians(lat))
      * cos(radians(lng) - radians(:lng))
      + sin(radians(:lat)) * sin(radians(lat)))) <= :radius_km
  Response: { listings: [...], total, page, totalPages }

GET /listings/:id
  Auth: Optional
  Action: Fetch listing detail + farmer profile + reviews + basket info
  Response: { listing, farmer, reviews, activeBasketsCount }

POST /listings
  Auth: Required (role=farmer)
  Body: { title, description, category_id, price_per_kg, unit, available_qty,
          min_order_qty, harvest_date, expiry_date, is_organic, pincode, images[] }
  Action: Create listing with status='active'
  Response: { listing }

PUT /listings/:id
  Auth: Required (role=farmer, must own listing)
  Body: Same as POST (partial allowed)
  Response: { listing }

DELETE /listings/:id
  Auth: Required (role=farmer, must own listing)
  Action: Soft delete (sets status='expired')

GET /listings/farmer/mine
  Auth: Required (role=farmer)
  Query: status, page, limit
  Response: { listings, stats: { totalSold, totalRevenue, activeCount } }

--- ORDER ROUTES (/orders) ---

POST /orders
  Auth: Required (role=consumer)
  Body: { listing_id, quantity, delivery_address, delivery_lat, delivery_lng,
          delivery_instructions, basket_id (optional) }
  Action:
    1. Check listing is active and has sufficient qty
    2. Calculate: subtotal = quantity * listing.price_per_kg
                  platform_fee = subtotal * 0.05
                  delivery_fee = calculateDeliveryFee(farm_lat, consumer_lat) [see Section 5]
                  total = subtotal + platform_fee + delivery_fee
    3. Create Stripe PaymentIntent:
       stripe.paymentIntents.create({
         amount: Math.round(total * 100),  // paise
         currency: 'inr',
         customer: consumer.stripe_customer_id,
         metadata: { orderId: <temp_uuid>, farmerId, consumerId },
         payment_method_types: ['card', 'upi'],
         application_fee_amount: Math.round(platform_fee * 100),
         transfer_data: { destination: farmer.stripe_account_id }
       })
    4. Create order with status='pending_payment'
    5. Return client_secret to consumer app
  Response: { order, client_secret, payment_intent_id }

POST /orders/confirm-payment
  Auth: Required (role=consumer)
  Body: { order_id, payment_intent_id }
  Action: Verify PaymentIntent status with Stripe → if succeeded update order
          status to 'confirmed' → deduct qty from listing → notify farmer via FCM
  Response: { order }

GET /orders/:id
  Auth: Required (any role involved in order)
  Response: { order, listing, farmer, consumer, delivery }

GET /orders/consumer/mine
  Auth: Required (role=consumer)
  Query: status, page, limit
  Response: { orders }

GET /orders/farmer/mine
  Auth: Required (role=farmer)
  Query: status, page, limit
  Response: { orders }

PUT /orders/:id/farmer-accept
  Auth: Required (role=farmer)
  Action: status → 'farmer_accepted' → find nearest available delivery partner
          → create delivery_assignment with status='offered' → notify delivery via FCM
  Response: { order }

PUT /orders/:id/farmer-ready
  Auth: Required (role=farmer)
  Action: status → 'ready_for_pickup' → notify assigned delivery partner

PUT /orders/:id/pickup-confirm
  Auth: Required (role=delivery)
  Action: status → 'picked_up' → notify consumer with OTP

PUT /orders/:id/delivery-confirm
  Auth: Required (role=delivery)
  Body: { otp }
  Action: Validate OTP → status → 'delivered' → trigger payout job (Bull queue)
  Response: { order }

PUT /orders/:id/cancel
  Auth: Required (role=consumer or farmer)
  Body: { reason }
  Action: Cancel order → if payment captured, initiate Stripe refund
          → update listing qty back → notify other party

--- COMMUNITY BASKET ROUTES (/baskets) ---

POST /baskets
  Auth: Required (role=consumer)
  Body: { listing_id, name, target_families, min_total_kg, expires_at,
          pincode, delivery_address, delivery_lat, delivery_lng }
  Action: Create basket with status='open' → creator auto-joins
  Response: { basket }

GET /baskets
  Query: pincode, listing_id, status
  Auth: Optional
  Response: { baskets }

GET /baskets/:id
  Response: { basket, members: [{ user, quantity_kg }], listing }

POST /baskets/:id/join
  Auth: Required (role=consumer)
  Body: { quantity_kg }
  Action:
    1. Add consumer to basket_members
    2. Update community_baskets.current_total_kg
    3. Update current_families count
    4. If current_total_kg >= min_total_kg AND current_families >= target_families:
       Lock basket (status='locked') → notify all members to complete payment
    5. Create individual orders for each member linked to this basket
  Response: { basket, order }

POST /baskets/:id/lock
  Auth: Required (role=consumer, must be creator)
  Action: Force-lock basket early if conditions partially met (admin override)

--- DELIVERY ROUTES (/delivery) ---

PUT /delivery/availability
  Auth: Required (role=delivery)
  Body: { is_available, lat, lng }
  Action: Update delivery_profile

GET /delivery/assignments/mine
  Auth: Required (role=delivery)
  Response: { assignments }

PUT /delivery/assignments/:id/respond
  Auth: Required (role=delivery)
  Body: { accepted: true/false }
  Action: If accepted → update order.delivery_id → status='farmer_accepted'
          If rejected → find next nearest delivery partner (max 3 attempts)

PUT /delivery/location
  Auth: Required (role=delivery)
  Body: { lat, lng }
  Action: Update delivery_profile.current_lat/lng → emit via Socket.io to consumer

--- STRIPE ROUTES (/stripe) ---

POST /stripe/farmer/onboard
  Auth: Required (role=farmer)
  Action:
    1. If no stripe_account_id: stripe.accounts.create({ type: 'express', country: 'IN',
       capabilities: { card_payments: {requested:true}, transfers: {requested:true} } })
    2. stripe.accountLinks.create({ account, refresh_url, return_url, type:'account_onboarding'})
    3. Return onboarding URL
  Response: { url }

GET /stripe/farmer/status
  Auth: Required (role=farmer)
  Action: stripe.accounts.retrieve(stripe_account_id) → check charges_enabled
  Response: { onboarded, charges_enabled, payouts_enabled }

POST /stripe/webhook
  Auth: None (Stripe signature verification via stripe-signature header)
  Action: Handle events listed in Section 1

--- ADMIN ROUTES (/admin) ---
All require role=admin.

GET /admin/users?role=&search=&page=&limit=
GET /admin/listings?status=&page=&limit=
GET /admin/orders?status=&from_date=&to_date=&page=&limit=
PUT /admin/users/:id/verify         → sets farmer_profiles.is_verified = true
PUT /admin/users/:id/deactivate     → sets users.is_active = false
GET /admin/analytics                → total orders, GMV, active farmers, active consumers

SECTION 8: DELIVERY FEE CALCULATION
================================================================================

Function: calculateDeliveryFee(farmLat, farmLng, consumerLat, consumerLng)
  Uses Google Maps Distance Matrix API (not Haversine — actual road distance)

ENDPOINT CALL:
  GET https://maps.googleapis.com/maps/api/distancematrix/json
    ?origins={farmLat},{farmLng}
    &destinations={consumerLat},{consumerLng}
    &mode=driving
    &key={GOOGLE_MAPS_API_KEY}

FEE STRUCTURE (INR):
  0–3 km    → ₹15 flat
  3–7 km    → ₹25 flat
  7–15 km   → ₹35 flat
  15–25 km  → ₹50 flat
  >25 km    → ₹50 + ₹2 per km beyond 25km
  Minimum   → ₹15
  Community basket: delivery_fee / number_of_basket_members (split equally)

Store result in order.delivery_fee at order creation time. Never recalculate after.

SECTION 9: MSG91 OTP INTEGRATION
================================================================================

API ENDPOINT: POST https://api.msg91.com/api/v5/otp
Headers:
  authkey: {MSG91_AUTH_KEY}
  Content-Type: application/json
Body:
  {
    "template_id": "{MSG91_TEMPLATE_ID}",
    "mobile": "91{10-digit-phone}",
    "authkey": "{MSG91_AUTH_KEY}",
    "otp": "{6-digit-otp}"
  }

OTP GENERATION:
  const otp = Math.floor(100000 + Math.random() * 900000).toString()
  const hash = await bcrypt.hash(otp, 10)
  Store in otp_sessions with expires_at = NOW() + 10 minutes

OTP VERIFICATION:
  1. Find otp_sessions record by phone where is_used=false and expires_at > NOW()
  2. If attempt_count >= 5 → reject (rate limit)
  3. bcrypt.compare(submittedOtp, hash)
  4. If match → set is_used=true → proceed
  5. Else → increment attempt_count

SECTION 14: SECURITY REQUIREMENTS
================================================================================

1. All API routes except /auth/otp/send and /auth/otp/verify require valid JWT
2. Role-based access: check req.user.role in every controller
3. Resource ownership: when farmer edits a listing, verify listing.farmer_id === req.user.id
4. Stripe webhook: always validate signature with stripe.webhooks.constructEvent()
5. OTP rate limiting: max 5 attempts per phone per 10 minutes (tracked in otp_sessions)
6. API rate limiting: use express-rate-limit 7.x
   - /auth/otp/send: 5 requests per hour per IP
   - All other routes: 100 requests per minute per user
7. Input validation: ALL incoming request bodies validated with Joi before controller
8. SQL injection: never use raw queries; always use Sequelize ORM methods
9. S3 bucket: private ACL only; serve via CloudFront signed URLs
10. HTTPS only in production; HTTP → HTTPS redirect in Nginx
11. Helmet.js for HTTP security headers
12. CORS: restrict origins to known app domains in production
13. Phone numbers: store in E.164 format, validate with regex /^\+91[6-9]\d{9}$/

SECTION 15: ERROR HANDLING STANDARDS
================================================================================

All API responses must use this structure:

SUCCESS:
  { "success": true, "data": { ... }, "message": "..." }

ERROR:
  { "success": false, "error": { "code": "LISTING_NOT_FOUND", "message": "..." } }

HTTP STATUS CODES:
  200 → OK
  201 → Created
  400 → Bad Request (validation error)
  401 → Unauthorized (no/invalid token)
  403 → Forbidden (valid token, wrong role or not owner)
  404 → Not Found
  409 → Conflict (e.g., already joined basket)
  422 → Unprocessable Entity (business logic error)
  429 → Too Many Requests
  500 → Internal Server Error

Create error codes (all caps, snake_case):
  AUTH_OTP_EXPIRED, AUTH_OTP_INVALID, AUTH_OTP_MAX_ATTEMPTS,
  LISTING_NOT_FOUND, LISTING_INSUFFICIENT_STOCK, LISTING_NOT_ACTIVE,
  ORDER_NOT_FOUND, ORDER_ALREADY_CONFIRMED, ORDER_CANNOT_CANCEL,
  BASKET_FULL, BASKET_LOCKED, BASKET_EXPIRED, BASKET_ALREADY_MEMBER,
  PAYMENT_INTENT_FAILED, STRIPE_ACCOUNT_NOT_READY,
  DELIVERY_NOT_AVAILABLE, DELIVERY_OTP_INVALID

Create a global error handler in backend/src/middlewares/errorHandler.js
Register it as last middleware in app.js

SECTION 18: PLATFORM FEE AND PAYOUT LOGIC
================================================================================

PLATFORM FEE: 5% of subtotal (order.platform_fee)
DELIVERY FEE: Per Section 8 (order.delivery_fee)
FARMER PAYOUT: order.subtotal - order.platform_fee
               (delivery fee goes to delivery partner separately)
DELIVERY EARNINGS: order.delivery_fee - 10% platform cut

PAYOUT TIMING:
  - Farmer: triggered immediately when order status → 'delivered'
  - Delivery partner: triggered immediately when order status → 'delivered'
  - Both via Stripe transfers to their connected accounts

PAYOUT JOB (Bull queue):
  Queue name: 'payouts'
  Job data: { orderId }
  Job logic:
    1. Fetch order, verify status='delivered'
    2. Calculate farmer payout: subtotal - platform_fee
    3. stripe.transfers.create({ amount, currency:'inr', destination: farmer.stripe_account_id,
       transfer_group: orderId })
    4. Update order.stripe_transfer_id and order.farmer_payout_amount
    5. Send push notification to farmer with payout amount
  Retry: 3 attempts with exponential backoff (1s, 5s, 30s)
  On permanent failure: alert admin via notification, log to Winston
